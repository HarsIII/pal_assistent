Save inspected: Steam, single-player/co-op world (11 player entries present),

Tooling: `scripts/run_phase0.py`, `save/inspector/`, `save/differential/`

## 1. Estructuras encontradas (structures found)

- **Wrapper format**: a 12-byte header (`uncompressed_len`, `compressed_len`,
  3-byte magic, 1-byte save_type) wraps every file except `UserOption.sav`.
  Magic observed: `PlM` (Oodle) on every file in this save. `PlZ` (zlib) and
  `CNK` (chunked/Xbox) are known from community sources but not present here.
- **GVAS payload**: standard Unreal SaveGame structure (header + property bag
  + trailer), UE 5.1.1, `SaveGameFileVersion=3`.
- **Per-file top-level structures**, all VERIFIED present and their entry
  counts confirmed by direct parsing (see `SAVE_FORMAT.md` for the full
  table): `CharacterSaveParameterMap`, `ItemContainerSaveData`,
  `BaseCampSaveData`, `GroupSaveDataMap` (guilds), `MapObjectSaveData`,
  `DynamicItemSaveData`, `WorkSaveData`, `DungeonSaveData`,
  `FoliageGridSaveDataMap`, and others -- 21 distinct top-level/nested
  structures under `Level.sav`'s `worldSaveData` alone.
- **File roles observed**: `Level.sav` (world state), `LevelMeta.sav` (day
  counter, timestamp), `LocalData.sav` (map UI, boss flags, treasure points),
  `WorldOption.sav` (difficulty/settings), `GlobalPalStorage.sav` (Palbox,
  account-level), `UserOption.sav` (client settings, account-level,
  uncompressed), `Players/<uid>.sav` (per-player progress/records),
  `Players/<uid>_dps.sav` (per-player `SaveParameterArray` -- role UNKNOWN).

## 2. Propiedades encontradas (properties found)

The Save Researcher's `SchemaWalker` discovered the full generic GVAS
property vocabulary in actual use in this save: `IntProperty`, `Int64Property`,
`UInt16Property`, `FloatProperty`, `ByteProperty`, `BoolProperty`,
`StrProperty`, `NameProperty`, `EnumProperty`, `StructProperty` (both
"nested property bag" and "raw" forms -- e.g. `Guid`, `DateTime`, `Vector`,
`FixedPoint64`, `Color`), `ArrayProperty` (both the generic `{"values": [...]}`
shape and several game-specific "raw binary" custom-decoded shapes), and

Full per-file property listings and the complete discovered-field inventory
(hundreds of distinct paths) are generated by `scripts/run_phase0.py` into
`reports/_generated/` -- not committed here because several examples are
snippets of real personal save data (nicknames, base names). Regenerate
locally at any time; the tool is fully reproducible.

## 3. Campos de Pal (Pal fields)

`worldSaveData.CharacterSaveParameterMap` holds **both Pals and players**
(1351 entries total: 10 with `IsPlayer=True`, 1341 with a `CharacterID`).
Confirmed fields relevant to breeding (name VERIFIED, meaning INFERRED from
community naming -- see `SAVE_FORMAT.md` for the full table and caveats):

`CharacterID`, `Gender`, `Level`, `Exp`, `Talent_HP`/`Talent_Shot`/`Talent_Defense`
(candidate Potential/IV stats), `PassiveSkillList`, `EquipWaza`/`MasteredWaza`
(active skills), `Rank` + `Rank_HP`/`Rank_Attack`/`Rank_Defence`/`Rank_CraftSpeed`
(candidate condensation rank + per-stat boosts), `IsRarePal` (candidate Alpha
flag -- **not confirmed**, could instead mean a color/shiny variant),
`SlotId` (container + slot location), `OwnerPlayerUId`/`OldOwnerPlayerUIds`,
`Friendship*` fields, `WorkSuitabilityOptionInfo`, `NickName`, `SkinName`,
`HP`/`ShieldHP`, `UniqueNPCID` (set on named/boss Pals).

No per-instance Partner Skill field exists -- consistent with the intended
domain model where `PartnerSkill` is species-level static data, not saved
per Pal.

## 7. Campos desconocidos (unknown fields)

- `.SaveData.Local_MaxFriendshipPalIds` (in `LocalData.sav`): unrecognized
  `MapProperty` value type; the parser's fallback guess is wrong and
  corrupts the rest of that file's parse. This is the one open gap blocking
  full `LocalData.sav` support (see `SAVE_FORMAT.md` for the exact
  mechanism).
- `IsRarePal`: strong candidate for "Alpha," but not confirmed against
  in-game behavior -- could instead denote a rare color/shiny variant, or
  something else entirely.
- `BaseCampSaveData.ModuleMap` passive-effect `type`/`work_hard_type` enum
  values: structure is known, meaning of the integer codes is not.
- `Rank_HP`/`Rank_Attack`/`Rank_Defence`/`Rank_CraftSpeed`: presumed
  per-stat condensation boosts, not independently verified.
- `Players/<uid>_dps.sav`: parses fine (a flat `SaveParameterArray` of 9600
  entries), but its purpose is undetermined -- not yet investigated.

## 8. Campos no encontrados (fields not found / not yet located)

No explicit field named anything like "PartnerSkillLevel" or a per-instance
Partner Skill reference was found on Pal entries -- expected, since Partner
Skill is species-level data (not saved per Pal), but this should be
re-confirmed once species-level static data (a game master data table, not
part of the save at all) is sourced in a later phase. No incubator- or
egg-hatching-specific timer field was located yet within the structures
inspected in this pass (eggs appear under `DynamicItemSaveData` per the
vendored parser's `rawdata/dynamic_item.py`, but incubation-specific state
was not specifically searched for in this pass).

## 9. Problemas (problems encountered)

1. **Compression format mismatch with ecosystem assumptions.** Most
   available community documentation and tooling (including the official
   `palworld-save-tools` package) assumes zlib (`PlZ`) compression. This
   save uses Oodle (`PlM`), which the official package does not support at
   all, and has not supported since it stopped being maintained in October
   2024.
2. **Hard crashes in raw binary decoders.** Even after fixing decompression,
   the official package's `rawdata/*.py` decoders `raise` on any trailing
   bytes they don't recognize, which happens because the game has added
   fields since those decoders were written. This crashed the entire parse
   of `Level.sav`, not just the affected sub-structure.
3. **A web-search-derived claim turned out to be wrong.** Initial research
   suggested a specific upstream pull request added Oodle support and was
   merged; the GitHub API showed it is in fact still open, from an
   unmerged fork. Resolved by verifying directly against the API rather than
   trusting the summary.
4. **`LocalData.sav` still does not fully parse** (see Unknown fields,
   above) -- a genuine, currently-unresolved gap, not swept under the rug.
5. **No `git` available on the development machine**, so the project has no
   version control yet. Plain files on disk for now.

## 10. Hipótesis (hypotheses -- explicitly not treated as fact)

- `Talent_HP`/`Talent_Shot`/`Talent_Defense` are the in-game "Potential" (IV)
  stats referenced in the target objective format (Section 15 of the
  original spec: "Potential: HP 100, ATK 100, DEF 100"). Values observed are
  small integers (e.g. 13, 14, 58), consistent with a 0-100-ish scale.
- `IsRarePal` is the Alpha flag. Alternative hypothesis: it denotes a
  different rare-variant concept (e.g. a unique color pal). Only 4 of 1341
  Pal entries have it set to `True` in this save, consistent with Alpha
  being rare, but that alone doesn't distinguish between the two hypotheses.
- `Rank` is the condensation ("soul") star rank, and `Rank_HP`/`Rank_Attack`/
  `Rank_Defence`/`Rank_CraftSpeed` are the per-stat boosts condensing
  sometimes grants. Values observed (7-20 range) are consistent with small
  percentage-style boosts, but this is not confirmed.
- `BaseCampSaveData.ModuleMap` entries with `passive_effects` correspond to
  base facilities/effects that could include a Breeding Farm's own
  modifiers -- worth targeted investigation once the domain model needs
  base-camp breeding modifiers.

## 11. Próximos pasos (next steps)

   project's own stated method: change one specific thing in-game (e.g. feed
   a Pal to raise Potential, or condense one), save, diff `Level.sav` before
   and after, and see exactly which path moves. This is the correct way to
   turn today's hypotheses into VERIFIED facts, and the tool already exists
   (`save/differential/differ.py`) -- it was only demonstrated on
   `LevelMeta.sav` in Phase 0 for speed; running it on `Level.sav` backups is
   straightforward but slower (each backup is several MB).
2. **Resolve the `LocalData.sav` gap** by either sourcing a newer fork
   commit, or writing a small local patch to the specific
   `Local_MaxFriendshipPalIds` map-value type following the same
   log-and-continue pattern already used elsewhere in the vendored fork.
3. **Do not proceed to the domain model (Phase 2) by inventing field
   meanings.** Every INFERRED item in this report should be either confirmed
   via differential analysis or explicitly left as a documented assumption
   with low confidence before `domain/PalInstance` is designed around it.
4. **Investigate `Players/<uid>_dps.sav`** and the `IsRarePal` /
   `BaseCampSaveData.ModuleMap` enum questions above before they become load
   -bearing assumptions in later phases.
5. **Decide on version control.** No `git` is installed on this machine;
   recommend installing it (or an alternative) before Phase 1 grows the
   codebase further, so history isn't lost.
6. **Await user direction before starting Phase 1** (formal Domain Model),
   per the project's own development rule: implement, test, verify, and
   document one phase before starting the next.
